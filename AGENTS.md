# AGENTS.md

This is a guide for AI coding agents, and the humans running them, working on or with **CanIToolCall**. Agents are welcome here: most of our contributions so far came from agents, and we want to know what you are trying to do.

## What this project is

CanIToolCall is a neutral conformance suite and public matrix for **tool-call and reasoning parsers** in inference engines (vLLM, SGLang, llama.cpp, Ollama and HF transformers).

- **Fixtures** are recorded raw model outputs with an expected parse and a provenance record.
- **Adapters** replay the fixtures through each engine's *own* parser code, offline, and then **checks** judge the results.
- **Results** feed the matrix at <https://redd34.github.io/canitoolcall/>.

A one-screen summary is in [`llms.txt`](llms.txt).

## Tell us your goal (please do this first)

Open an **Agent check-in** issue: <https://github.com/redd34/canitoolcall/issues/new?template=agent_checkin.yml>. It takes a minute. Say what you are trying to achieve, what blocked you, and what would have helped. We read every one, and we use them to decide what to build next. You can also say so in your PR description.

## Setup and the commands that matter

```sh
uv sync                                   # dev env (Python >= 3.10)
uv run pytest -q                          # tests; engine tests skip if the engine env is absent
uv run ruff check src tests scripts && uv run ruff format --check src tests scripts && uv run mypy
uv run canitoolcall validate              # fixtures against the spec
bash scripts/engines/<engine>.sh          # isolated, pinned engine env (vllm, sglang, transformers, llamacpp, ollama)
uv run canitoolcall run --engine <engine> --family <slug> --env HF_HUB_OFFLINE=1
uv run python scripts/engines/prefetch_hf.py   # tokenizer/template files only, never weights
```

## Verify an upstream fix PR

For Python engines (vLLM, SGLang, transformers), one command swaps the PR's changed files into the pinned engine, replays the fixtures at the PR's base and head commits, restores the pinned files, and prints what changed:

```sh
bash scripts/engines/sglang.sh
uv run python scripts/verify_upstream_pr.py --engine sglang --pr 41319 --family gemma4 --json report.json
```

Example output (sglang#41319, run on 2026-09-27):

```text
sgl-project/sglang#41319  base 3ed56a341 -> head 941d0d2bb
fixtures replayed: 48   fixed: 3   regressed: 0   other changes: 0
  gemma4/edge-values-key-with-space: fail -> pass
  gemma4/nested-objects-and-arrays: fail -> pass
  gemma4/numeric-arguments: fail -> pass
```

The exit code is 0 when nothing regressed, 1 on a regression, and 3 if the PR can't be replayed on the pinned engine (it depends on other unreleased changes).

**Report in the tracking issue here**, not only upstream. Paste the output and the base and head SHAs. Ollama (Go) and llama.cpp (C++) rebuild complete sources into separate temporary workspaces. Use `--engine ollama --pr 18663 --family glm` and `--build-jobs 2`. Existing vocab-only GGUFs are required. See [compiled verification](docs/compiled-verification.md).

## Rules (please follow them; they protect the project's credibility)

1. **Never fabricate** fixtures, results, scores or citations. Every fixture needs `provenance`, and a template-rendered fixture must be regenerated by its script, never typed by hand. If you can't run something, say so.
2. **Expected values describe what a correct parser should return** according to the model's format, not what an engine happens to do. Don't edit expected values to make a result pass.
3. **Before commenting upstream, follow that project's policy on AI-assisted contributions.** llama.cpp prohibits AI-written bug reports. transformers asks first-time contributors not to open agent-written issues or PRs. vLLM requires AI use to be disclosed. When in doubt, post here and let a human take it upstream.
4. **Disclose AI assistance** in your PR description (the template has a field for it).
5. **Stay read-only against the network.** No telemetry, and no calls to real endpoints from tests. `probe` sends a key only to the `--base-url` you give it.
6. Keep PRs to one fixture family, one adapter or one fix, and run the checks above before opening them.

## Where things are

| Path | What |
|---|---|
| `fixtures/<family>/*.jsonl`, `spec/` | the corpus and its JSON Schemas |
| `docs/formats/<family>.md` | each model family's raw format, with sources |
| `scripts/fixtures/<family>/` | fixture generators (template renders, pinned revisions) |
| `src/canitoolcall/adapters/` | one adapter per engine |
| `src/canitoolcall/checks.py`, `runner.py`, `probe.py` | the checks, the replay runner and the live probe |
| `results/<date>/` | committed snapshots, `triage.jsonl` (the cause of every failure) and repro scripts |
| `site/templates/`, `src/canitoolcall/matrix.py` | the static matrix site |
